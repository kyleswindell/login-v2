## Documentation Rules

* Keep docs close to the feature or architectural decision they describe.
* Prefer normal Markdown links and add Obsidian links when the connection is important for graph navigation.
* Update feature docs in the same change that introduces or changes behavior.
* Keep implementation details specific enough that future Codex sessions and collaborators can continue safely.
* Treat research files as planning inputs and summarize durable project rules in `docs/standards/`.
