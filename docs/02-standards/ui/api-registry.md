## 1. Purpose

This registry is the durable source-of-inventory for Login App 2.0 UI APIs. It indexes Foundation Elements, Components, Patterns, planned Pattern sub-APIs, source surfaces, UI Reference routes, standards docs, and known ownership gaps.

Use this registry before adding or correcting a UI Element, Component, Pattern, Blade component, JavaScript controller, CSS namespace, UI Reference page, or feature-owned UI partial.

Active implementation progress is tracked in `docs/08-active/`, not here.

## 2. Registry Rules

- Treat Foundation Elements, Components, and Patterns as approved, deferred, prohibited, represented, or planned Login App APIs.
- Carbon may inform coverage, reasoning, accessibility, and interaction completeness, but Login App owns the final API decisions.
- Every planned API reference must list where it appeared and which owner should fill it in later.
- Do not link a planned API to a UI Reference route until that route exists.
- Do not create feature-local workarounds for APIs listed as planned, deferred, or gated.
- When an API disposition changes, update this registry, the owning standard, the UI Reference route, and tests in the same pass.

## 3. Disposition Vocabulary

| Disposition            | Meaning                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Approved API           | Login App has approved this API contract. Current build/review proof is tracked in `docs/08-active/`.                                       |
| Deferred API           | Do not use yet. A trigger condition and acceptance path are required before implementation.                                                 |
| Do not implement       | Not applicable until a product decision changes.                                                                                            |
| Planned registry gap   | Name has appeared in standards, source, UI Reference, or review, but does not yet have a complete owner standard and route/source contract. |
| Represented by pattern | A Carbon/component-like concept is intentionally owned by a Pattern rather than a standalone Component.                                     |

## 4. Reference Tracking Standard

Every unresolved API, route, partial, or source owner must track:

- first seen
- current references
- intended owner
- current disposition
- next action before use

## 11. Registry Maintenance

Update this registry when:

- a standards doc is added, renamed, or removed
- a UI Reference route is added, renamed, or removed
- a Blade component, Pattern helper, JavaScript controller, or CSS namespace becomes public
- a planned API is referenced by a Component or Pattern standard
- a deferred API becomes approved
- a Carbon component or pattern is intentionally excluded from Login App coverage

Do not use this registry as a substitute for the owning API standard or the active implementation sync. The registry indexes ownership and durable disposition; the owning Element, Component, or Pattern standard defines rules; `docs/08-active/` tracks current work progress.
