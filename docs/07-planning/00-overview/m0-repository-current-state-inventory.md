# M0 Repository Current-State Inventory

Parent: [Planning Index](../index.md)

## 1. Purpose

Provide the authoritative current-state inventory of repository structure and non-UI runtime surfaces required by GitHub issue #29 and M0 Goal 02.

This document records what exists at the pinned baseline, how runtime surfaces are registered, which owner is currently evidenced, which authority or lifecycle state applies, and which contradictions or unknowns require later disposition.

It does not select final target placement, perform migration, or reopen ADR-0005, ADR-0006, or ADR-0007.

## 3. Scope

### In Scope

- root files and repository configuration
- `.agents`, skills, memory, baselines, and scoped instruction files
- `app/Core`, `app/Platform`, `app/Surfaces`, `app/Http`, and other application branches
- `Modules`
- routes and middleware
- commands, jobs, events, listeners, notifications, policies, providers, and registries
- configuration files and canonical or transitional key families
- documentation, indexes, standards, planning, architecture, features, flows, database docs, runbooks, and AI working material
- scripts, stubs, Docker, operations, build tooling, and generated-output boundaries
- namespaces, physical paths, aliases, and compatibility paths
- registration, reachability, and invocation evidence where safely obtainable

### Non-Goals

- final target topology
- physical moves
- runtime or key renaming
- route or URL migration
- schema changes
- broad implementation rewrites
- selecting final owners for contradictions
- treating file count as sufficient evidence
- duplicating the UI inventory owned by issue #30
- duplicating the persistent-data inventory owned by issue #31
- duplicating the test inventory owned by issue #32
- reopening accepted Goal 01 decisions

The inventory follows:

- [ADR-0006: Tenant, Instance, Workspace, Principal, Actor, And Invocation Vocabulary](../../01-decisions/adr-0006-tenant-instance-workspace-principal-and-invocation-vocabulary.md)
- [ADR-0007: Owner, Registry, And Identifier Key Conventions](../../01-decisions/adr-0007-owner-registry-and-identifier-key-conventions.md)

Every material item uses these required fields:

Supporting tooling metadata may use `_reviewed` and `_review_note`. Those fields do not replace the required inventory schema.

Application `ownership_area` values are `core`, `module`, and `ui`. Repository work owners such as Docs, Ops, and Tests are recorded in `current_responsibility` or evidence and use `ownership_area: not_applicable`.

## 6. Evidence Method

The inventory generator:

1. reads the exact Git tree at the pinned baseline
2. records tracked paths, object identifiers, sizes, namespaces, document metadata, and safe header summaries
3. identifies material directory, file, runtime, configuration, documentation, instruction, script, tooling, and generated-boundary entries
4. attempts read-only Laravel discovery commands when the local environment can boot
5. records command failures rather than converting failed discovery into guessed registration
6. seeds a separate classification file without silently treating inference as review
7. renders reviewed classifications into this document
8. validates that every material item is reviewed and traceable

The generator does not read `.env`, secret stores, private storage, logs, runtime session files, database contents, or reusable credentials.

| `app/Core/Modules/PackageLoader.php` | Loads Core and enabled optional definitions in dependency order. | Record Core module-lifecycle infrastructure and dependency registration behavior. |
| `app/Core/Modules/PackageRegistrar.php` | Dynamically registers providers, views, translations, migrations, and route groups from package definitions. | Record the registration mechanism separately from declared package files. |

| `.gitignore` | Defines secret, dependency, runtime, generated asset, test artifact, documentation state, IDE, and operating-system boundaries. | Record ignored boundaries without inventorying ignored contents. |

These anchors are starting evidence, not permission to skip the complete baseline review.

## 13. Security And Privacy Boundaries

The inventory must not contain:

- `.env` values
- passwords or password hashes
- API keys, access tokens, refresh tokens, or session secrets
- private keys or complete certificates
- recovery codes
- production personal data
- database row contents
- private-storage contents
- reusable credentials
- unrestricted logs

The inventory may record field names, configuration key names, storage classes, safe fingerprints, command names, route names, file paths, metadata, classifications, and redacted failure summaries.
