# UI Implementation Sync

This file tracks active UI standards implementation and review alignment for the current Batch F workspace.

Standards files define the target API contracts. The UI API registry indexes durable ownership and disposition. This file tracks temporary build/review state: standard API, expected source/API, source implementation state, UI Reference proof state, test state, queue item, review state, and next action.

Do not treat this file as canonical UI standards truth. When Batch F closes, completed state must be reconciled into the appropriate standards, planning, worklog, or archive surface. Durable post-Batch tracking should move to `docs/07-planning/ui-system-implementation-index.md`, not into `docs/02-standards/ui`.

## Status Vocabulary

| Status | Meaning |
| ------ | ------- |
| Accepted baseline | Previously accepted as sufficient for current Batch F review surface. |
| Installed API | Source/API exists, but UI Reference proof may still need sync. |
| API proof synced | UI Reference page now renders the installed API and focused tests cover the proof surface for this pass. |
| Needs API proof sync | UI Reference page must be checked or corrected to prove the installed API. |
| Needs recovery review | Standards, source, UI Reference, and tests must be compared component by component. |
| Recovery queued | A component-specific queue item now owns correction/proof work in the P2-F-CQ-129 sequence. |
| Deferred / gated | No production API should be used until the documented gate is met. |
| Represented by pattern | The subject is tracked through a Pattern rather than a standalone Component. |
| Needs audit | Current implementation/proof state is not yet verified against the standard. |
