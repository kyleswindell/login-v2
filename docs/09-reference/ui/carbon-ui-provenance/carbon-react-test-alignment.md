# Carbon React Test Alignment

## Purpose

This support reference inventories Carbon React component test folders and maps them to Login App UI test targets. It supports co-located Login App tests under `resources/views/components/ui/{component}/__tests__/` and `resources/views/elements/{element}/__tests__/`.

This is not a parity mandate. Carbon tests are evidence for completeness, accessibility, and behavior review. Login App standards decide which behavior is enforced locally.

For the Carbon-wide owner matrix, package-level theme/style/type/motion/layout/element/color tests, and local test creation instructions, use [Carbon Test Coverage Matrix](carbon-test-coverage-matrix.md).

## Classification Legend

| Classification                   | Meaning                                                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Blade contract                   | Portable to PHP Blade render tests.                                                                           |
| Browser behavior                 | Portable to Playwright interaction tests.                                                                     |
| Static governance                | Portable to source, registry, docs, or forbidden-API tests.                                                   |
| Documentation/reference evidence | Belongs in `index.md` or support docs until adopted by a standard.                                            |
| React-only / not portable        | React callback, hook, render prop, controlled rerender, or snapshot behavior with no direct Blade equivalent. |
| Discrepancy candidate            | Carbon and Login App differ; document before enforcing.                                                       |

## Accordion Pilot Notes

Carbon Accordion renders list semantics with `ul`/`ol` and `li` items. Login App currently renders a `div` root with `section` items. Carbon supports root disabled, ordered accordions, Escape close from the trigger, and a skeleton component. Login App currently supports item disabled state, single/multiple mode, contained/flush/compact/icon-start/scrollable variants, and click/native button activation through app JavaScript.

The current Accordion pilot enforces installed Login App behavior only. A green pilot test run must not be treated as Carbon parity, final accessibility approval, visual approval, or manual component approval. Carbon assertion coverage and drift candidates are recorded in `resources/views/components/ui/accordion/__tests__/index.md`.
